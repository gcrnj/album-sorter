# Wedding Photo Sorter

A local macOS app for reviewing, arranging, and safely renaming wedding photos. The interface runs on Next.js; its Node route handlers use macOS `osascript` for native file selection and filesystem operations for renaming. It does not upload images or use a database.

## Run locally

From this folder, install dependencies once and start the app:

```bash
npm install
npm run dev
```

Open [http://127.0.0.1:3000](http://127.0.0.1:3000). The development server binds to localhost only. Keep the terminal window open while using the app. Stop it with Ctrl+C.

## Use

1. Choose **Open folder** and select the folder containing the photos. The app reads supported image files in that folder only; subfolders are excluded.
2. Drag photos to reorder them, use the filename search, or use each card’s up/down controls. **Add photos** opens a native multi-file picker and adds supported files from the selected folder to the end of the sequence; you can then move them into place.
3. Choose **Preview rename** to review the current and proposed filenames. Prefix, starting number, and interval can be changed there.
4. Choose **Save** to apply the full rename plan. Nothing in the selected folder is changed before this action.

The default names are `Wedding_00100.jpg`, `Wedding_00200.jpg`, and so on. Extensions and image bytes are preserved. The app generates display thumbnails with macOS `sips` in a separate temporary cache; when `sips` cannot decode a format, it falls back to serving the original read-only for browser preview. Thumbnail support depends on the macOS image codecs available on that Mac.

## Safety details

- Save validates all selected sources and destination names, checks for unrelated-file collisions, and stages changed files under unique temporary names in the same directory. It claims each destination with an exclusive same-filesystem hard link before removing the temporary name, so a late collision cannot overwrite a file.
- The app hashes file contents before and after rename, and attempts to restore original paths if a rename step fails. This is a best-effort rollback, not a crash-proof filesystem transaction.
- The last successful rename can be reversed with **Undo last save** while the app’s Node process is running. The undo record is held in memory and is lost if the server restarts.
- Search, selection, reordering, and filename settings are in-memory editor state. Closing or refreshing with unsaved changes triggers a browser warning.
- Rename changes directory-entry metadata such as modification timestamps as the operating system normally does; image contents and embedded photo metadata are not rewritten.

## Checks

```bash
npm test
npm run lint
npm run build
```

Tests use temporary directories and generated byte fixtures; they do not read or modify your photo folders. The macOS chooser requires the app to be run on macOS, and the production build alone cannot exercise the native dialog.
